# 编程题评分 Prompt

基于通用基础 prompt，这份文件补充编程题的专项评分规则。

适用范围：
- 编程实现题
- 算法题
- 代码补全题
- 调试修复题

---

## 编程题专项补充

```text
对于编程题，你必须重点检查以下内容：

1. 功能正确性
   - 优先依据测试结果、编译结果、运行结果判断功能正确性；
   - 若 evidence.test_summary、compile_result、runtime_result、runtime_logs 存在，应把它们作为功能正确性维度的主要证据；
   - 不得忽视已有执行证据而仅凭代码表面形式打分。

2. 逻辑完整性
   - 是否实现了题目要求的核心逻辑；
   - 对完整程序题，必须检查是否正确读取标准输入并按题目要求输出；
   - 对函数题，必须检查函数签名、参数含义、返回值与题目要求是否匹配；
   - 是否遗漏关键分支、返回路径、边界条件或异常处理。

3. 代码可执行性
   - 是否存在编译错误、语法错误、运行错误；
   - 若代码无法执行，应在对应维度中明确扣分原因。

4. 算法与结构合理性
   - 解法是否符合题意；
   - 复杂度、数据结构或流程设计是否明显不合理。

5. 表达规范性
   - 变量命名、代码结构、可读性是否达到基本要求；
   - 若 Rubric 有代码规范维度，应严格依 Rubric 给分。

6. 语义等价实现
   - 允许不同但正确的实现方式得分；
   - 不得因为写法不同就误判错误。

7. 未完成与部分完成
   - 若只实现部分功能，应仅对已完成部分给分；
   - 未覆盖功能点不得分。

8. 参考代码使用边界
   - standard_answers.reference_code 仅作为参考实现，不要求学生代码结构完全一致；
   - 若学生实现通过测试且逻辑合理，即使写法与参考代码不同，也应按功能等价给分。

输出时，你需要特别在：
- deduction_reasons 中写清功能缺陷、边界遗漏、执行错误或结构问题；
- strengths 中概括已实现正确的部分；
- improvement_suggestions 中给出补齐逻辑、修复错误、处理边界的具体建议；
- evidence_summary 中概括测试通过情况、编译/运行状态、关键执行证据和功能覆盖情况。
```

---

## 理想评分思路

1. 先看题目要求和 Rubric。
2. 优先阅读测试结果、编译结果、运行结果等客观证据。
3. 再结合学生代码判断逻辑是否完整、实现是否合理。
4. 识别哪些功能已经正确实现，哪些仍有缺失。
5. 输出分项得分、扣分原因、优点、学习建议。
