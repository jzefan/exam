# 智能岗位能力模型生成工具方案

## 1. 现状与需求分析
当前系统底层已经具备了非常完善的数据结构设计：
*   **版本控制**：由 `JobModelProject` 统管，下属多个 `JobModel` 版本，通过 `version` 和 `is_current` 区分。
*   **多模态知识挂载**：`SourceDocument` 负责存储原始 JD 或参考文件。
*   **标准基座**：`JobModelTemplate` 可存储“江苏省1650各产业链要求”等公共模板。
*   **树形能力结构**：`JobModel` -> `CompetencyDimension` (维度) -> `Skill` (技能) -> `SkillKnowledgePoint` (技能知识点)。
*   **智能映射**：`SkillKpMapping` 表支持将动态技能与底层固定知识点通过 `confidence` (置信度) 绑定。

**核心目标**：激活这些沉睡的数据结构，打造一个前端可见、AI 驱动的“解析→生成→校准→输出”核心闭环，让业务人员无需从零手填。

## 2. 核心闭环实施计划

### 阶段一：后端 AI 引擎构建 (Generate & Map)
**任务**：实现“JD -> 结构化岗位模型”的转换。
1.  **JD 解析接口**：提供文件上传接口（复用现有文件服务），提取纯文本。
2.  **大模型萃取 (LLM Extraction)**：构建 Prompt，将杂乱的 JD 文本提取为结构化的 JSON 数据（包含 Dimension、Skill、Required Knowledge）。
3.  **向量匹配 (RAG/Vector Search)**：将提取出的 Knowledge 关键词，与系统中那 1300+ 个标准 `KnowledgePoint` 进行匹配计算。
4.  **模型持久化**：将 AI 结果写入数据库，建立 `CompetencyDimension` 等层级，并自动生成 `SkillKpMapping`，`match_type` 设为 `ai`，记录 `confidence` 置信度。

### 阶段二：前端“工作台”构建 (Parse & Calibrate)
**任务**：提供“AI 生成与人工微调”的完美交互体验。
1.  **极简上传页 (Parse)**：类似刚刚做好的题目导入界面，支持拖拽 JD 或选择平台标准模板（L2）进行“克隆派生”。
2.  **双栏校准界面 (Calibrate)**：
    *   **左侧**：展示 JD 原始文本（可选折叠）及全局控制（如设置当前版本号 `v1.2` 和更新说明）。
    *   **右侧核心区**：展示 AI 生成的能力树（维度 -> 技能 -> 知识点）。
    *   **AI 辅助标识**：对于通过向量匹配到的知识点，展示置信度（如绿色的“98%匹配”，橙色的“60%疑似”）。
    *   **人工微调**：用户可点击修改技能名称、增删关联的底层知识点，调整掌握程度（`level`）。
3.  **多版本管理页 (Output)**：展示一个企业 Project 下的所有历史岗位模型，支持一键查看版本间差异（Diff）和对外导出共享。

### 阶段三：公共基座预置 (Template Initialization)
**任务**：将“江苏省1650产业链人才要求”部分代表性内容转化为 `JobModelTemplate` 存入系统，为企业提供“开箱即用”的标准参照。

## 3. 技术路径建议
我们无需对现有数据库进行大规模重构，重点在于开发 **AI Pipeline 接口** 和 **前端交互页面**。这与刚刚完成的“题目导入与校准”在技术栈上高度同源，可以复用其成功的设计语言（shadcn/ui，大圆角极简流式布局）。

## 4. 下一步行动
如果您认可此方案，我们可以选择从以下任意一点开始：
1. **[前端优先]**：先使用 Mock 数据，把“AI 模型生成与微调校准”的交互界面搭建出来，直观体验闭环。
2. **[后端优先]**：先开发大模型提示词（Prompt）与知识点向量匹配算法，跑通“给一段JD，返回一棵带置信度的技能树”的后端接口。
