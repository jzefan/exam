私有化之后，维护比 SaaS 更贵

  • 无法统一在线升级，每校一份实例，版本会分叉
  • 升级要远程进校内环境、做回归、准备回滚，约 2 次/年 × 2 人日
  • 安全补丁与依赖更新约 3 人日/年；远程答疑限 30 工单约 6 人日
  • 备份巡检、配置变更约 5 人日/年
合计维护工作量≈18 人日/年
按 1,300 元/人日折算≈2.34 万元/年

续年运维低于 2 万就是赔本做。合同必须写明服务边界，否则"卖一次、维护一辈子"。

    四、必须写进合同的「不含范围」

    报价之所以能压在 20 万内，靠的是严格的范围边界。以下任一项被默认包含，项目就会亏。

    • 源码交付 / 知识产权转让：不含。如需源码另行议价（通常为授权费的 3–5 倍），且需单独约定二次开发责任边界
    • 定制功能开发：不含。按 1,500–2,000 元/人日另计，或单独立项
    • 服务器 / GPU / 本地大模型算力：不含。学校自备或代购另计
    • 大模型 API 调用费：不含。AI 阅卷、出题、OCR 走第三方 API，按实际用量实报实销或约定年额度，不能包死在总价里
    • 等保测评费 / 第三方渗透测试费：不含。仅配合整改，测评与费用由学校承担
    • 教务系统直连 / 接口开发：不含。仅提供标准模板导入；直连教务库需另计
    • 驻场、超场次现场培训、7×24 SLA：不含。默认工作日远程响应
    • 学习通数据抓取的长期可用性：不承诺。该能力依赖第三方页面结构，对方改版会失效，建议列为可选项或不纳入验收

    五、学校需提供的前提（写进附件，避免延期责任）

    基础设施

    • 服务器：建议 8C16G / 200G SSD 起，Docker Engine + Compose，内网固定 IP；启用学习通浏览器自动化或本地模型时资源上调
    • 域名 + HTTPS 证书（或校内 CA 证书）
    • 网络出口：放行 5 家大模型 API 与镜像源；若无出口，需提供校内 OpenAI 兼容模型端点（*_base_url 已支持）
    • 数据库备份存储空间

    数据与人员

    • 统一身份认证接口文档与测试账号（CAS / OAuth2 / LDAP）；若不对接，接受本地账号 + 批量导入
    • 学生、班级、课程、知识点、题库按模板提供，并指定数据核对人
    • 1 名校内系统管理员对接 + 2–3 名种子教师参加培训
    • 明确验收人、验收窗口与试运行考试安排

    可量化的验收口径

    • 8 个 Compose 服务健康检查全绿，前端 / 后端 / runner 可访问
    • 2 场模拟考试全流程跑通：组卷 → 发布 → 学生端作答 → 客观题判分 + AI 主观题阅卷 → 成绩与教师确认
    • 数据库备份恢复演练 1 次成功
    • 管理员 / 教师手册交付 + 2 场培训签到
    • 许可文件生效、人数与有效期校验通过
    给供方的三条自我保护：
    • 版本分叉要封顶：合同写明「仅维护交付版本 + 每年 2 次合并上游安全与功能更新」，不承诺无限跟进主线新功能。
    • 首校要做成可复制交付包：第 1/3/8/9 项的产品化成果必须沉淀为通用产物，否则第二所学校仍要重复 69 人日，低价就变成长期负债。
    • AI 效果先 POC：若学校改走本地小模型，多模型协同评分与 OCR 效果会下降，务必在签约前用真实样卷跑一次，把效果预期写进验收附件。
