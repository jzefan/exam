本地服务器不需要 GPU

算力主要发生在外部大模型 API，校内服务器只负责编排、排队、存储与 I/O。 因此硬件投入是一台常规应用服务器，而持续成本是按人次线性增长的 API 调用费 —— 按下面的口径，每人次约 0.08 元，1 万人次 / 学期约 800 元。

每人次公式：主观题调用数 = 主观题数 Q × [ (1 − 复用率 r) × 2 + r × 1 ] = Q × (2 − r)。 默认 Q=5、r=15% → 约 9.25 次评分调用 / 人次，再加填空与讲解约 0.7 次 → 合计约 10 次调用 / 人次。 评分单次 prompt 由 common-base.md + 题型模板（各约 2.4 KB）加题干、标准答案、评分量表与学生答案组成，估算输入 2,500 tokens、输出 400 tokens（结构化 JSON）。

系统：Linux（Ubuntu 22.04 / 麒麟 / 统信均可）、Docker Engine 24+ 与 Compose v2、Python 3.12 镜像、Node 22 镜像、PostgreSQL 17。不需要 GPU、不需要 CUDA、不需要推理卡。

存储（按人次）

  • 每次评分落 1 个 task + 3–4 个 JSON 快照 + 5–10 条审计事件，约 10–20 KB / 题
  • 5 道主观题 ≈ 50–100 KB / 人次 → 1 万人次约 0.5–1 GB 数据库
  • 上传附件才是大头：按 0.5 MB/人次 → 1 万人次 5 GB；含拍照作答按 2 MB/人次 → 20 GB
  • 镜像 + 系统 + 日志约 30–50 GB；每日全备保留 30 天，按数据量 ×2–3 预留

网络与出口

  • 校内千兆即可：作答流量约 1–3 MB/人次（含题目图片），500 并发约 10–30 Mbps
  • API 出口流量很小（每次请求约 3–6 KB），关键是稳定低延迟与白名单，不是带宽
  • 需放行：api.deepseek.com、dashscope.aliyuncs.com、ark.cn-beijing.volces.com、openrouter.ai（如启用）、镜像源与 NTP
  • 对外只需 443；校内固定 IP + 域名 + HTTPS 证书

峰值并发才是真瓶颈

  • 阅卷是异步队列，服务器 CPU 压力低；瓶颈在模型厂商的 QPS / TPM 额度
  • 500 人 × 5 题 × 2 次 = 5,000 次调用；30 分钟出分约需 17 并发，10 分钟出分约需 50 并发
  • 默认 API 额度常在 5–20 并发量级，大考前须提前申请提额或错峰发布
  • 建议：分批交卷 / 关闭仲裁 / 提高复用率 / 设置队列上限与失败重试

五、如果学校要求「数据不出校」：本地 GPU 对照

结论：经费有限时不建议。把 API 换成本地推理，等于把「每人次几分钱的可变成本」换成「十几万到几十万的一次性硬件 + 专人运维」，且评分质量与并发都要重新验证。

  • 需自建 OpenAI 兼容端点（vLLM / Ollama），把 *_base_url 指向校内服务；代码已支持，改造量小
  • 但要同时替换三类能力：文本评分（2 个角色）、视觉识别（Qwen-VL，题目/手写答案 OCR）、embedding（课程资料 RAG，切模型需重新入库，向量维度必须一致）
  • 单卡 24G（L20 / 4090）跑 32B 量化模型仅约 5–10 并发，500 人考试出分要排队数小时
  • 要支撑 30–60 并发，建议 2×A100 80G 或 4×L20 48G，另配高速 NVMe 与 UPS；硬件一次性约 15–40 万
  • 还需模型选型、量化评测、Prompt 重调、效果 POC 与长期运维，远超 13.8 万软件费
  • 折中做法：文本评分走 API、附件与原始数据留校内，并在合同里写明数据范围与脱敏规则；或由学校统一采购校内模型网关

六、把 API 成本压到最低（按代码现有开关）

  • 保持 arbiter_enabled=false（默认）：仲裁默认关闭是有意为之，代码注释明确写了「等 QPS 配额够再开」。开启会同时抬高费用与峰值并发。
  • 用好答案复用：grading_answer_reuse_similarity_threshold=0.94，标准答案趋同的简答/填空题复用率高，复用路径只花 1 次等价判定，替掉 2 次评分。
  • 客观题不进模型：单选/多选/判断本地判分；填空题已有精确匹配 + 签名缓存，只有真正不一致才调 DeepSeek。
  • 一次性任务与人次脱钩：AI 出题、题目/图片 OCR、导入时知识点匹配、课程资料 embedding，都按「题目数 / 资料量」发生，不随考生人次增长，应单列预算而非摊进人次单价。
  • 选低价模型档：Qwen 有 ¥0.96/¥2.4 与 ¥2.998/¥8.993 两档刊例，DeepSeek Flash 亦远低于 Pro；评分场景用 Flash/Plus 即可，成本可再降 60% 以上。
  • 错峰与大考前提额：提前 2 周向厂商申请 QPS/TPM 提额，验收时按「单场峰值人数 + 出分时限」跑一次压测。

七、前提、风险与来源

测算前提

  • 「人次」= 1 名学生参加 1 场考试；每人次 5 道主观题、复用率 15%、不开仲裁
  • 不含 AI 出题、OCR 识别、知识点匹配、资料 embedding 等一次性任务
  • token 与耗时为估算，实际随题干长度、评分量表复杂度、模型响应速度浮动
  • 费用为厂商刊例价估算，未计免费额度、缓存命中、批量折扣与代理加价

需要提前确认的风险

  • 数据与合规：学生答卷会发送至模型厂商，须经学校信息中心/教务审批，必要时做脱敏
  • 出口可用性：校内防火墙策略、DNS、证书链；无外网出口则退回本地 GPU 方案
  • 额度与限流：大考集中交卷可能触发 429，需队列与重试策略
  • 价格变动：模型迭代与调价频繁，建议按学期复核单价并设预算上限告警
  • 学习通自动化：Chromium 会话吃内存，且依赖第三方页面结构，改版会失效
