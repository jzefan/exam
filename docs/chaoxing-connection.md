# 学习通连接与阅卷

入口：阅卷中心 → 学习通（`/grading/chaoxing`）。流程为登录 → 教师课程 → 考试 → 考生姓名、学号 → 核对并保存答卷 → AI 评分 → 教师确认。已保存记录位于 `/grading/chaoxing/results`，断开学习通后仍可访问。没有创建学生账户、写入错题库或回填学习通成绩的接口。

## 本地启动

教师使用普通网页，无需安装客户端或扩展。下面的依赖安装发生在运行本系统的服务器上。

```bash
cd backend
UV_CACHE_DIR=/tmp/uv-cache uv sync --extra chaoxing --extra dev
PYTHONPATH=src UV_CACHE_DIR=/tmp/uv-cache uv run alembic upgrade head
UV_CACHE_DIR=/tmp/uv-cache uv run --extra chaoxing playwright install chromium
# Linux 服务器第一次安装可使用 playwright install --with-deps chromium
cd ..
bash scripts/run-chaoxing-dev.sh
# 另一个终端：
cd frontend
pnpm dev
```

沿用 `backend/.env` 中的数据库和认证配置。启动前按项目现有方式启动本地数据库。不要同时占用 8000 端口。可用 `EXAM_CHAOXING_PORT` 修改脚本监听端口，并同步修改开发代理。也可设置 `EXAM_CHAOXING_BROWSER_EXECUTABLE` 使用管理员提供的 Chromium 可执行文件。

已有本地后端运行时，先停止原开发后端再使用上述脚本。不要在同一数据库旁额外启动完整 API 作为旁路连接服务，因为现有启动流程会恢复待执行的评分任务。

应用代码默认关闭连接器；生产部署默认启用。运行 `./scripts/deploy.sh --target backend`（同时更新前端用 `--target app`）时，会为服务器 `shared/env/backend.env` 补上缺失的 `EXAM_CHAOXING_ENABLED=true`，但保留已有明确的 `false`。生产镜像安装 `chaoxing` 依赖、Chromium 和 Linux 运行库，入口按开关选择一个或两个 worker。部署前会在新镜像中实际启动并关闭浏览器；依赖或浏览器不可用时，停止发布，保留旧后端在线。

启用学习通时，部署先完成镜像构建、浏览器检查和迁移，再停止旧后端并启动新后端，健康检查通过后切流。期间 API 短暂中断，学习通临时登录会丢失；建议避开正在阅卷和考试的时段。切换失败会尝试启动保留的旧容器并恢复原 Nginx 配置。Compose 用共享命名卷 `exam_chaoxing_lock` 将两个槽位的锁放到 `/run/chaoxing/connector.lock`，防止误启动两个消费者。仍只支持同一 Docker 主机单实例；跨主机扩容需先拆分会话和队列。前端单独部署不会启用或重启后端。

若管理员先前显式关闭过功能，需将服务器 `shared/env/backend.env` 中的开关改为 `true` 后重新部署。服务器不要设置开发机的 `EXAM_CHAOXING_BROWSER_EXECUTABLE` 路径，生产 Compose 会指定镜像内的 `/usr/local/bin/chaoxing-chromium`。Chromium 默认直接通过 `https://cdn.npmmirror.com/binaries/chrome-for-testing/<版本>/<平台>/<文件>` 下载，避免新版 Playwright 自动附加 `builds/cft/` 后与镜像路径不匹配。可用 `CHROMIUM_FOR_TESTING_DOWNLOAD_HOST` 指向相同目录结构的内部镜像；镜像不可用时构建自动重试官方 CDN。首次升级会下载浏览器，镜像构建时间和体积会增加；同一 Playwright/锁文件版本的后续代码发布会复用 Docker 浏览器层，除非手动清理 Docker builder 缓存。

## 登录行为

- 点击连接后，服务器为当前教师建立独立的非持久化 Chromium context。窗口显示学习通官方页面的截图，键盘、点击和人工拖动被发送到该页面。二维码、用户名密码、验证码是否可用，以学习通当前页面和服务器网络为准。
- 登录输入会经过本系统服务器。用户名和密码会按本系统教师账号分别用 `EXAM_SECRET_KEY` 加密保存在数据库，并在下次打开登录框时自动填写；不会自动提交。只有配置至少 32 个字符的非默认 `EXAM_SECRET_KEY` 时才启用保存，密钥轮换后旧凭据无法解密。教师可在登录框清除已记住的账号。请使用 HTTPS；不要在代理、APM 或调试工具中记录此路径的请求体、截图或浏览器协议。代码不记录输入、不导出 Cookie/token，不开启 trace/HAR/video，不保存浏览器 storage state。
- 登录后点击“已完成登录，验证连接”，必须同时检测到学习通身份 Cookie 和可识别的教师课程页面才算连接成功。成功后关闭登录页面，保留同一隔离 context 用于读取。
- Cookie 仅在服务器浏览器会话中使用，不返回给网页。会话仅属于当前本系统用户，管理员也不能读其他用户的会话。
- 点击“断开”关闭 context 并清除临时记录与 Cookie；已加密保存的登录账号会保留以便下次填写。默认空闲 30 分钟、绝对 2 小时后清理。截图轮询不会延长空闲时间。仅关闭弹窗或退出网页不会立即关闭服务端会话，会由超时清理。服务重启需要重新登录。
- 课程、考试、考生名单和答卷在当前连接会话内缓存 5 分钟；返回页面或重复点击时复用读取结果。课程/考试/名单/答卷各自的“刷新”会绕过缓存重新读取，学习通登录失效、断开连接或会话清理时缓存一并清除；服务重启也会自然清空。
- 并发上限默认 3 位教师，每个会话串行执行浏览器操作。连接功能不调用 LLM。

环境变量：`EXAM_CHAOXING_ENABLED`、`EXAM_CHAOXING_MAX_SESSIONS`、`EXAM_CHAOXING_IDLE_SECONDS`、`EXAM_CHAOXING_MAX_AGE_SECONDS`、`EXAM_CHAOXING_BROWSER_EXECUTABLE`、`EXAM_CHAOXING_LOCK_PATH`。后端 HTTP 接口位于 `/api/chaoxing`，沿用本系统 Bearer 认证和教师/管理员角色边界。

## 读取边界与验收

当前适配 ArkLoop 已识别的 `fycourse` 教师 HTML 课程页、`mooc2-ans` 考试/批阅页及 LayUI 固定列。仅使用已知读取地址，不接收任意 URL；读取页只发送 GET/HEAD，另有少数由学习通页面脚本自己发出的只读列表查询使用 POST（见下），仍不开放页面点击和成绩提交。来源 URL、签名和 Cookie 不发往前端。

### 名单表由页面脚本异步拉取

学习通批阅页的名单是 LayUI 表格，服务端返回的 HTML 里 `<tbody>` 是空的，行由页面自己的 XHR 在加载后填充：

- 该 XHR 是 **POST** `/mooc2-ans/exam/test/markresult-new`（`markPaper-list.js` 里 `method: "post"`），响应是 `{code,count,data:[{id,createUserName,loginName,markUrl,answerScore,…}],size,total}`。
- 读取通道原先只放行 GET/HEAD，这条 POST 被拦掉 → 表格永远是空的 → 名单页只剩表头。**这是“读取考生读到 0 条”的根因，不是账号权限问题。**
- 现在只对**逐个点名的只读列表路径**（`READ_POST_PATHS`，当前仅 `markresult-new`）放行 POST，其余 XHR 仍然中止；同时把请求体里的 `size` 抬到 `LIST_PAGE_SIZE`（500），避免一页只返回十几条把班级名单截断。
- 放行后仍需等页面自己渲染出行：读取时若页面含 `layui-table-body`，会等 `tr[data-index] td` 出现（最多 8 秒）再取 HTML。
- 名单页默认停在「已交」页签（`state=1`），所以读出来的是**已提交**的考生；考试本身没有已提交答卷时返回 409「该考试暂无已提交的答卷」，不再报成“未识别到考生记录”。
- 考生的身份取行内单元格 `td[data-field="id"]`（答卷 id）；列表 URL 里的 `id` 是班级关系 id，**整页所有学生共用**，只能兜底。

所有列表明确标记 `complete: false`。最多跟随 5 个同一考试或同一答卷的可识别分页链接；JavaScript 分页、不同结构的 iframe、学校统一认证跳转和 JSON 课程结构需要根据真实账号页面继续适配。无法识别页面会报错，不把它当作“零条数据”。源页面加载时浏览器仍可能请求其中的图片资源。程序答案保留换行和缩进，未知分数保留 `null`。

跟随嵌套页面时只比对考试/答卷身份参数（`id`、`testId`、`paperId`、`testUserRelationId`）；`clazzid`、`cpi`、`courseid`、`enc`、`t`、分页参数允许不同，因为名单页与考试入口本来就分属不同班级上下文。跳转到不支持的页面时报错会附带落地站点与路径（不带查询串，签名仍留在服务端）。

名单页只把含数据单元格的行当作考生：表头行（`<thead>` 或整行只有 `<th>`）不会生成“姓名/学号”这种假考生，姓名与学号也只取数据单元格。页面确实没有考生行时报错，不伪造一条记录。

### 题目展示与题库一致

「查看答卷」和「AI 评分」两个页面都通过 `pages/chaoxing/question-preview.ts` 把读到的题目折成 `IQuestion`，再用题库自己的 `QuestionPreviewCard` 渲染，因此题号、题型徽章、题干、参考答案的写法与题库、阅卷中心完全相同，题型走 `question-preview-utils` 的同一张映射表（题型串不落在这六类里时照原样显示，不猜默认题型）。答题纸只有纯文本，没有选项、难度和知识点，所以适配器留空这些字段并配合 `hideMeta hideSourceBadge hideScoreAndDifficulty` 隐藏对应装饰，满分改在 `trailing` 显示源站真实满分；考生答案作为卡片内容插在题干之后、参考答案之前，点击卡片才展开参考答案。

排查真实页面结构时，可先创建本地目录 `/tmp/exam-chaoxing-pages`（或用 `EXAM_CHAOXING_DUMP_DIR` 指定），此后“跳转到了不支持的页面”“未识别到考生记录”“未识别到课程作业列表项”和“未提供作业读取凭据”四条路径会把刚读取的页面写入该目录。目录不存在时不写诊断文件；留档仅用于本地适配解析器，定位完请删除。登录页不经过该读取通道，不会被留档。

### 新版泛雅课程页没有隐藏的 enc 输入

`mooc2-ans-vue/fanyav3/tch` 及其同类课程页是 Vue 外壳，各模块以 iframe 挂载；页面里**没有**老一代 `mycourse/tch` 用的 `<input id="workEnc">` / `<input id="enc">`（实测真实课程页只有 3 个课程参数输入，`workEnc` 出现 0 次）。旧版 `mooc1.chaoxing.com/mooc2/work/list` 因而不能覆盖这种课程页。

新版课程页的任务 iframe（`task.chaoxing.com/task/index`）会自行发起 `GET /task/getTaskDataLists`，参数包括课程 ID、筛选项和分页信息。读取器现在在同一个已登录浏览器页面中捕获该列表响应，不重建签名参数；返回的作业标题会列出。这个新任务类型的考生答卷入口仍需单独适配，所以列表项暂不可读取考生答卷。

创建诊断目录时，还会留存任务模块 HTML、未放行请求的方法和路径，以及作业列表接口的状态码、参数名和返回条数；不会记录接口响应正文。诊断文件只用于本地定位，可能包含课程页面标记，排查后请删除。登录页不经过该读取通道，不会被留档。

连接已由教师手动验证。不同学校、课程及分页结构仍需用获授权的账号核对以下范围，当前采用逐份核对后导入，不自动导入整班：

1. 在拟部署服务器上登录，确认验证码/风控和会话有效期，核对教师权限。
2. 至少两个学期和两门课程，核对课程、考试列表及空列表。
3. 选择包含已交、未交考生且有多页的考试，核对人数、姓名和学号。
4. 至少两份含程序题/图片答案的答卷，核对每题题干、参考答案、分值和作答内容。
5. 验证两位教师隔离、断开、空闲到期、源站登录失效及服务重启。

保存前必须勾选已核对本份答卷的题目和分值。服务器仅保存本会话刚读取的快照，通过哈希拒绝过期预览或前端伪造的答卷内容。完整性尚未自动证明，保存份数与源站已提交人数分别显示；题目满分合计与源试卷满分不符时不生成最终成绩。

考生列表可对整场考试启动 AI 评分：按已提交名单逐份读取、保存并提交主观题评分任务，搜索框不影响批量范围。已读取的提交人数与考试显示人数不一致时按钮禁用，可重新读取名单。批量导入不会代替教师逐份核对，因此记录保持“完整性待核对”，即使已有 AI 建议分也不形成最终成绩；教师在单份答卷页核对后保存，可确认相同快照而不重建评分任务。批量进度显示入队、无新增任务与失败数，任务入队后由既有后台队列异步评分；批量读取期间需保持页面打开。

## 评分与持久化

- 四张独立表 `chaoxing_grading_exams/candidates/items/audits` 存储教师所属考试、姓名学号、题目评分和操作审计。学习通账号凭据另存于 `chaoxing_credentials`，仅加密密文；不落库 Cookie 或带签名的 URL。账号只保存源 UID 的哈希用于区分来源；候选人不关联本系统学生账号或错题库。每位本系统教师仅访问自己的记录，管理员角色也不会自动获得其他教师的外部答卷。
- 重复保存相同快照返回已有记录；作答、题目或分值变化时生成新的答卷版本，保留旧版确认分及评分快照。历史版本只读。
- 主观文字题依据题干、参考答案及满分进入现有主评/复核引擎，使用当前激活的评分配置版本；模型输入不追加姓名、学号。代码题按静态评阅处理，不声称运行过测试。题型不支持或缺少评分依据的题目转人工评分。客观题沿用有效源分，不调用模型；未知源分不当成零分。
- 客观/主观只有一个口径：`chaoxing/question_types.py` 把源站题型标签折成本系统六类题型，客观 = `choice/true_false/fill_in`、主观 = `short_answer/essay/code`，与 `exams/router.py` 的 `_OBJECTIVE_QUESTION_TYPES` 保持一致。**只有主观题会入队调用模型**，`ai_type()` 对客观题型一律返回 `None`。解析器与保存答卷都按标签判客观题；页面的 `objective` class 只在标签不认识时兜底。
- 真实页面把题型和满分印在同一个标签里（`(单选题, 2.0分)`），客观题**没有**任何分值字段。满分按 分值字段 → `data2` → `fullScore` → 题型标签 → 输入框 `placeholder` 的顺序取，题型只保留 `…题` 部分用于展示和路由。不都以「题」结尾的标签（如 `(名词解释, 20.0分)`）取括号内的中文串，否则分值会跟着题型一起显示。缺了这一步，整卷满分只有主观题部分，会误报“满分不一致”且不生成最终成绩。
- 只有答复本身存在附件里（图片、下载/附件链接）且没有可读文字答案时才算“需人工评分”。曾把答复区里任何 `<a>`/`<img>` 都算成附件，导致一份真实答卷 42 题全被标成需人工，主观题一道都进不了模型。
- **答复是上传的文本/代码文件时，读取器会取它的文本内容参与评分**（学生把 `.py` 当作业交上来时，只看"含附件"等于放弃这类题）。边界收紧在四点：只调用源站自己的附件元数据接口 `GET /ananas/status/<objectid>`（与源站"下载"按钮同一路径）**并且在答卷页面的上下文里发这两个请求**（源站 CDN 会拒绝缺少 Referer 与 `X-Requested-With` 的裸请求，实测裸请求返回 403），只跟随该接口返回、且是 https + chaoxing 域名 + 无写操作特征的下载地址，只处理后缀在文本白名单内（`py/txt/java/c/cpp/js/sql/md/json/...`）的附件，大小上限 512KB。**内容只在内存里解码为文本、不落盘**；图片、二进制、超限、非源站地址或重定向一律放弃，题目保持"需人工核对"，绝不当作已作答。每次放弃的原因（对方域名、重定向目标、字节数）写入 `*-attachment-*` 留档便于定位。
- 题型标签为「简答题」但题干要求编写程序（`编写程序`/`编写代码`/`补全代码`/`运行结果` 等）时按 `code` 路由，使用编程题提示词（检查输入输出、边界条件），仍只做静态评阅、不执行学生代码。
- 每份答卷点击 AI 评分，只为待评分和失败题入队。重复点击、已生成建议分或已确认的题目不会重新调用模型。队列串行处理，与浏览器会话独立；页面轮询不触发模型。默认沿用 `EXAM_ARBITER_ENABLED` 设置，未启用时不调用第三模型。
- AI 建议分和教师确认分分别保存，支持小数。教师可补充缺失满分、输入确认分及评语；版本校验防止旧页面覆盖新确认。旧模型任务完成时也不能覆盖教师结果或新答卷。
- 后台中断时，已提交数据库的模型结果直接恢复，未确定完成的调用标记失败，需教师主动重试，不自动造成重复费用。失败重试是新的模型调用，已发出的失败/中断调用可能计费。
- 已确认小计包含教师确认分和客观题已知源分；最终成绩只在当前答卷全部题目处理完成且满分核对一致时产生。导出的未完成最终成绩留空，学号按文本输出，防止前导零丢失及公式注入。
