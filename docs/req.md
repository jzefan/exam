# 一、AI主观题判题系统（核心模块）

## 2.1 题目与答案输入

### 2.1.1 输入方式

支持多种输入方式：

| 方式     | 说明         |
| ------ | ---------- |
| 拍照识别   | OCR识别题目与答案 |
| 图片导入   | 上传图片自动识别   |
| 文本导入   | 粘贴文本       |
| 文件导入   | Word / PDF |
| 手动输入   | 手工录入       |
| 考试结果导入 | 来自考试系统     |
### 2.1.2 OCR能力

功能：自动识别题目-- 自动识别学生答案 -- 识别代码 -- 识别公式
输出：题目，答案，题型，代码块
下文纠错： 针对识别出的乱码，利用 AI 结合题目语境进行“语义修复”。
### 2.1.3 标准答案输入

支持：手动输入，AI生成标准答案，从题库导入
支持：多个标准答案（主观题），评分要点，评分规则

# 三、AI判题机制（核心算法流程）

系统采用 **多模型协同评分机制**

架构：学生答案 -- Qwen评分模型 -- DeepSeek评分审核 -- Claude最终评分 -- 最终评分结果

1. 动态路由机制原则
	1. 高分主观题： 采用双模型并行评分。
	2. 争议处理： 当两个模型评分分差超过 15% 时，自动触发第三个模型（如 Claude 3.5 Sonnet）进行“终审仲裁”
2. 结构化评分模板：判题不应只靠 Prompt。系统需支持结构化评分量表
	1. 支持定义“关键知识点”的权重
	2. 反向扣分项： 定义“致命错误”（如代码死循环、医学考试原则性错误），一旦触碰直接降档。
## 3.1 模型角色定义

系统支持模型角色：

| 角色   | 说明   |
| ---- | ---- |
| 评分老师 | 初步评分 |
| 评分审核 | 审核评分 |
| 最终评判 | 最终评分 |
默认配置：

| 角色   | 模型       |
| ---- | -------- |
| 评分老师 | Qwen     |
| 评分审核 | DeepSeek |
| 最终评分 | Claude   |
## 3.2 不同题型评分规则

### 代码题评分

评分维度：功能正确性，代码可读性，语法正确性，算法效率，异常处理，代码规范
输出：维度评分，问题说明，优化建议，最终分数
增加**“沙箱运行”**验证。AI 负责代码风格和逻辑评价，而功能正确性应通过真实的单元测试（Unit Test）结果作为 AI 的输入。
### 简答题评分

评分维度：知识点覆盖，逻辑结构，准确性，完整性，表达能力
语义对齐： 简答题不仅仅是关键词匹配，应支持“意思对即可”的语义相似度分析。
### 开放性问题评分

评分维度：思维深度，逻辑性，创新性，论证能力
# 四、AI评分结果结构

每次评分返回：评分模型，各维度评分，综合评分，扣分原因，优点分析，改进建议
示例：
```
Qwen评分

功能正确性：30/40
代码可读性：20/25
语法正确性：15/15
性能：10/20

最终评分：75
```
# 五、人工干预系统

系统必须支持 **人工干预**

## 5.1 Prompt控制

用户可以定义：评分规则，评分维度，评分重点
示例：
```
请从知识点覆盖角度重新评分
请从逻辑性角度重新评分
```
支持：prompt模板 ，prompt管理 ，prompt保存
## 5.2 模型角色调整

管理员可以：重新分配模型角色
示例：
```
DeepSeek作为评分老师
Qwen作为评分审核
Claude作为最终评审
```
## 5.3 人工评分

功能：人工修改评分，添加评语
系统记录：人工修改日志
# 六、评分界面设计

采用 **左右布局**
```
┌─────────────────────────────┐
│ 输入区域        │ AI评分结果 │
│                 │           │
│ 题目            │ Qwen评分   │
│ 学生答案        │ DeepSeek评分│
│ OCR结果         │ 最终评分   │
│                 │           │
│ prompt输入      │           │
│                 │           │
└─────────────────────────────┘
```
功能区：输入区，AI评分区，prompt控制区，评分管理区
