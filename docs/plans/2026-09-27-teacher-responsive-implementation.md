# 教师端响应式实施任务

依据：[教师端整体响应式设计方案](./2026-09-27-teacher-responsive-design.md)。当前仓库存在通知中心未提交修改，本任务不改动该文件。

| 任务 | 负责人 | 主要文件 | 可验收结果 |
| --- | --- | --- | --- |
| T1 教师导航与工作台 | 主智能体 | `frontend/src/components/layout.tsx`、`frontend/src/pages/dashboard.tsx` | 教师电脑四入口；手机四项底栏；待办优先，入口指向正确业务；管理员与评估员导航保持可用 |
| T2 我的课程 | 课程子智能体 | `frontend/src/pages/courses/` | 课程列表、课程详情、学期与八项功能在手机可访问；平板与桌面正常布局 |
| T3 阅卷中心 | 阅卷子智能体 | `frontend/src/pages/grading/` | 手机队列→作答→评分→下一项；保存失败保留输入；现有按题/按学生及桌面功能保留 |
| T4 学生管理 | 学生子智能体 | `frontend/src/pages/students/` | 手机可选择班级、搜索、查看和单项操作；桌面表格与批量功能保留 |
| T5 跨模块视觉质检 | 独立质检子智能体，主智能体协调修复 | 不预设修改文件 | 对比成熟教务/办公软件的清晰度和密度；在 390/768/1440 宽度检查操作路径、遮挡、对齐、信息层级；不合格项返回对应负责人循环修复 |
| T6 集成验证 | 主智能体 | 测试与本地浏览器 | 相关类型检查、模块测试、真实核心流程；报告未覆盖风险 |

工作循环：实现 → 类型/模块检查 → 页面截图或浏览器检查 → 质检列出可复现问题 → 负责人修复 → 再检查，直到高优先级问题归零且核心任务可完成。视觉质检必须指出具体页面、宽度、元素和期望效果，不以主观“感觉不错”代替证据。

提交标准：所有计划功能在对应尺寸下可访问和操作；没有整页横向溢出、关键按钮被键盘/导航遮挡、hover 独占操作、菜单与权限不一致；现有桌面流程无明显回归。视觉反馈按功能阻断、操作困难、视觉噪声三个层级处理。商业软件对比用于检验信息密度和操作效率，不复制特定产品外观。

验证按仓库 `AGENTS.md` 分级：共享 Layout 属 L2，需相关测试与实际主流程；单页调整属 L1；低影响纯样式调整属 L0。只在用户明确要求时跑全量测试。对登录或数据不可得的页面，应区分“代码检查通过”与“真实页面已验证”，不能将前者写成后者。

## 本轮实施与验收记录

- T1：教师桌面导航补齐四入口，手机四项底栏；工作台显示待阅答案、最近课程和本机“继续上次阅卷”。请求失败有页内提示和重试，不将失败误报为空队列。
- T2：手机课程列表使用紧凑行，危险操作收进“更多”；课程详情在窄屏提供功能/学期选择，目录节点操作与目录清除移入菜单。现有八项功能仍以原 Tab 为业务入口，五组重整尚未实施。
- T3：手机阅卷可从队列进入作答、评分并确认下一项；平板作答/评分双栏；按题和按学生模式保留。评分失败保留输入，失效深链接回队列，本机最近任务按教师隔离。跨设备草稿和后端并发版本冲突检测未实施。
- T4：手机和平板学生管理采用班级选择、搜索、列表/详情及显式批量选择；1200px 起保留桌面侧栏表格。教师移除关联和管理员删除账号使用不同文案。
- T5：独立质检在 320/390/768/1024/1200/1279/1440px 的代表性页面实测，修复课程节点裁切、学生弹层空白与中宽表格拥挤、阅卷平板空白等问题；最终采样无 P1/P2 阻断、无整页横向溢出。
- T6：`npx tsc -b` 通过；受影响的导航、工作台、课程、阅卷、学生测试共 78/78 通过；浏览器在独立 4100/8100 端口使用模拟教师数据走通导航、查询、评分确认与下一项。本地未接真实数据库，模拟数据验收不能代替真实后端与真机验证。

尚未实测虚拟键盘、手机弱网、长代码和真实附件、复杂课程发布/编辑流程。上述项目与真实数据库上的权限及跨设备冲突属于后续验收，不纳入本轮“通过”结论。
