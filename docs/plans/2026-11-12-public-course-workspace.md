# 公开课程教师工作区

## 验收边界

- 只有平台管理员能发布、重新启用、停用课程短链接。
- 匿名访问只读公共目录、资料、题目和可复用试卷，不创建用户或工作区。
- 教师第一次创建内容时，在课程 URL 内注册/登录；使用平台同一账号体系。
- 课程入口提供独立界面，所有教学操作留在 `/c/:code` 下，不显示全站导航。
- 每位教师拥有独立学期、班级关联、学生关系、练习/考试、题目、资料和试卷。
- 公共资源可引用；个人新增资源不因挂到公共知识点而公开。
- 私有性同时覆盖列表、详情、关联引用、编辑删除及文件下载。

## 实施顺序

1. 统一课程/知识点/题目/试卷/资料的访问范围，收紧发布权限，关闭访客自动开户。
2. 增加无副作用的公共内容读取接口，修复教师个人题库在课程中的展示和组卷引用。
3. 建立课程独立布局与课程 URL 范围，复用已有教学页面，提供课程内认证和操作恢复。
4. 对匿名、普通教师 A/B、学校管理员、平台管理员进行定向测试；在独立 4100/8100 环境走主流程。

## 技术取舍

- 复用现有 CourseUserWorkspace、owner_id、uploaded_by 和 TeacherStudent，不创建第二套账号。
- 课程根知识点拥有者提供的基础内容是课程公共资源；其他教师新增内容保持私有。
- 新建题目进入当前教师自己的题库，课程聚合同时查课程基础题和当前教师关联题。
- 课程页面采用路由 basename 保留课程上下文，使已有页面内部导航仍在课程 URL 内。
- 不修改生产数据库，不部署；验证使用隔离数据库和独立端口。

- 前端定向回归：19 项通过，覆盖课程 URL、登录过期与旧请求竞态、登录注册表单、学期与班级关联、资料预览。
- `frontend: npx tsc -b` 通过；`git diff --check` 通过；改动后端文件的未定义名称与重复导入检查通过。
- 浏览器：隔离 SQLite 数据库，后端 8100、前端 4100；使用独立 Chrome 会话验证桌面 1365px 与手机 390px。
- 实际完成：匿名题目/试卷/PDF/Word 预览 → 课程内注册 → 返回新建学期 → 创建班级和学生 → 关联学期 → 创建个人题目 → 发布练习和考试 → 共享题与个人题组卷 → 上传和预览个人 PDF。

未跑全量测试套件，按项目规则仅验证本次影响模块。没有部署、修改生产数据库或执行迁移。浏览器上传验证隔离了自动 AI 入库请求，未调用真实外部模型；知识库权限通过模拟向量的接口测试验证。现存 SQLAlchemy 测试清理/关系警告与 Pydantic 弃用警告未扩展处理。

## 兼容性与数据约定

- 保留旧 `/course-share/:code` 路径，与 `/c/:code` 使用同一独立课程界面。
- 登录注册复用平台账号；从域名正常登录后，“我的课程”包含已经加入的课程。
- 停用短链接会阻止匿名预览和通过该链接进入；不会删除既有教师的个人数据。
- 原访客工作区字段保留用于兼容，新的公开入口不再自动开户、签发访客 token 或使用工作区密码。
- Word `.docx` 在浏览器解析，避免依赖服务器 macOS 转换工具；旧 `.doc` 保留原有转换及下载兜底。
