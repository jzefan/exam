# 题库导入智能识别增强设计

日期：2026-04-14

## 1. 背景

当前题库导入已经具备：

- `pdf / docx / md` 文件上传
- 标准模板识别
- 规则分段识别
- 单题 AI 补全
- 导入前人工审核

但老师对“导入不智能”的反馈是准确的。现有链路的关键缺口不在单题补全，而在整份文档的切题与结构识别：

- 非模板文档主要仍靠规则切题
- 段落边界利用不充分
- `[题型] / [答案] / [解析] / [难度]` 这类结构字段没有作为统一边界信号参与所有识别路径
- 前端只有上传后自动识别，没有明确的“AI 一键分析整份文件”动作
- 图片虽然能进入预览内容，但没有真正参与整份文档 AI 分析

本次设计目标是把题库导入升级为“双入口、双引擎”的稳定识别流程：

- `快速识别`：规则与模板优先，响应快，适合规范文档
- `AI 一键分析整个文件`：整份图文混合输入给 AI，输出严格 JSON，并与规则结果比对

## 2. 目标

### 2.1 功能目标

- 非模板文档能够稳定按段落和结构字段切分题目
- 一个题目至少对应一个段落，段落是切题的基础单位
- `[题型] / [答案] / [解析] / [难度]` 既是字段，也参与题目边界判断
- 前端提供明确的 `AI 一键分析整个文件` 按钮
- 后端支持整份文档图文混合 AI 识别，并强制要求模型输出合法 JSON
- AI 识别结果与规则识别结果进行比对，差异大的题目自动标记异常
- 图片支持进入 AI 分析，而不是只停留在文本占位或预览展示
- 后台出错时，前端必须立即结束等待，并给用户明确提示

### 2.2 非目标

- 不解决扫描版 PDF OCR
- 不做复杂试卷版面高保真还原
- 不保证远程失效图片一定可被 AI 正常读取
- 不在本轮中改造最终题目编辑器的数据结构

## 3. 总体方案

### 3.1 入口设计

上传文件后，前端提供两个入口：

- `快速识别`
- `AI 一键分析整个文件`

两者都进入同一个审核工作台，区别只在于生成草稿的来源不同。

### 3.2 两条识别路径

#### 路径 A：快速识别

- 标准模板检测
- 模板文档直接结构化解析
- 非模板文档走规则分题
- 规则生成 `draft`
- 对低置信或结构不完整题目继续走单题 AI 补全

#### 路径 B：AI 一键分析整个文件

- 先执行规则分题，生成 baseline
- 同时把整份文档文本和图片按顺序送给多模态模型
- AI 返回严格 JSON 的题目列表
- 后端将 AI 结果与 baseline 比对
- 差异大的题自动标记 `异常`
- 前端进入审核页时展示 AI 结果，但保留异常标记与人工修订能力

### 3.3 设计原则

- 模板优先：标准模板必须 100% 稳定
- 段落优先：一个题目至少一个段落，段落是智能识别的基本单位
- AI 不裸奔：AI 结果必须和规则结果对齐比对
- 出错快返：AI 失败、超时、格式错误都必须快速反馈，不允许用户无限等待
- 图片实参与：图片必须进入 AI 请求，不只是文本中的提示语

## 4. 规则分题增强设计

### 4.1 基本分题单位

文档先被拆成“段落块”而不是逐行扫描。段落块定义为：

- 被空行分隔的文本块
- 代码块作为单独块
- 单独图片行作为块
- 以 `[题型] / [答案] / [解析] / [难度]` 或 `题型：/答案：...` 开头的字段行单独作为块

每一道题至少由一个段落块组成，可扩展包含多个附属块。

### 4.2 题目开始信号

按优先级识别新题开始：

1. 强信号：序号型开头
   - `1.`
   - `1)`
   - `1）`
   - `[1]`
   - `【1】`
   - `1、`
   - `（1）`
   - `一、`
2. 中信号：题型型开头
   - `单选题 / 单选`
   - `多选题 / 多选`
   - `选择题`
   - `判断题 / 判断`
   - `填空题 / 填空`
   - `简答题 / 简答`
   - `论述题 / 论述`
   - `编程题 / 编程`
3. 结构信号：字段型开头
   - `[题型]`
   - `[题目内容]`
   - `[答案]`
   - `[解析]`
   - `[分析]`
   - `[难度]`
   - 以及对应的中文冒号形式

### 4.3 题目聚合规则

当前题建立后，以下块默认归属于当前题：

- 题干续写段落
- 选项段落
- 答案段落
- 解析段落
- 难度段落
- 图片段落
- 代码块

只有当出现新的题目开始信号时，才切换到下一题。

### 4.4 特殊边界规则

- 若一个段落同时包含序号和题干，则视为新题首段
- 若一个段落仅为 `[答案] ...`、`[解析] ...`、`[难度] ...`，它不单独成题，只附着到当前题
- 若文档首段不是明确题目起点，也要作为候选题起点保留，避免首题丢失
- 图片段落不能单独裂变成新题，必须附着到最近的当前题

## 5. AI 整份分析设计

### 5.1 前端输入结构

前端不再只上传 `raw_text`，而是上传：

- `raw_text`
- `source_format`
- `analysis_mode`
- `images`

其中 `images` 至少包含：

- `image_id`
- `url`
- `order`
- `page` 或 `block_index`
- `alt`（若有）

文本中保留图片锚点，例如：

```text
观察下图回答问题：
[IMAGE:image-3]
```

AI 可据此理解图片在文档中的相对位置。

### 5.2 AI Prompt 要求

后端新增“整份文档 AI 分析”专用 prompt，要求模型：

- 读取整份文档文本与图片
- 判断总题数
- 输出每题的结构化结果
- 只输出合法 JSON
- 不输出 Markdown、解释、注释
- 不能臆造缺失答案

### 5.3 AI 输出 JSON 结构

建议返回如下对象：

```json
{
  "questions": [
    {
      "type": "choice",
      "content_text": "题目内容",
      "options": { "A": "选项A", "B": "选项B" },
      "answer_text": "A",
      "analysis": "解析内容",
      "difficulty": 3,
      "raw_text": "识别出的原始片段",
      "images": ["image-3"]
    }
  ]
}
```

约束：

- `questions` 必须存在，且为数组
- `type` 只能是既有题型枚举
- `difficulty` 必须落在 `1-5`
- `options` 仅选择题返回
- `answer_text` 缺失时返回空字符串，不允许臆造

### 5.4 图片参与方式

多模态模型输入时同时携带：

- 规范化后的整份文本
- 图片 URL 列表
- 图片在文本中的锚点引用顺序

AI 输出中的 `images` 字段用于把图片重新挂回对应题目。

## 6. 规则与 AI 比对设计

### 6.1 比对目标

AI 结果不能直接信任，需要与规则分题 baseline 比对。

比对维度：

- 总题数是否一致
- 每题题型是否一致
- 题干相似度是否足够高
- 选择题是否缺选项
- 解析和难度字段是否缺失
- 图片是否成功挂到题目上

### 6.2 标记策略

#### 正常

满足以下条件时，题目保持 `待审核`：

- 题干存在
- 题型合法
- 与 baseline 无明显冲突

#### 缺答案

满足以下条件时，题目保留 `缺答案` 状态：

- 题干结构完整
- 只是没有答案

该状态允许继续导入。

#### 异常

满足以下任一条件时，标记 `异常`：

- AI 总题数与 baseline 差异过大
- 当前题无题干
- 选择题缺少必要选项
- 题型无法确定
- 题干与 baseline 差异极大
- 图片锚点无法回挂
- AI 返回字段结构非法

该状态不允许直接确认或导入。

### 6.3 差异过大阈值

第一版采用简单阈值：

- 总题数差值大于 `max(1, baseline * 20%)`
- 单题题干归一化后相似度低于阈值

阈值写死在后端，后续再按真实数据调整。

## 7. 前端交互设计

### 7.1 上传态

上传区域保留全屏工作台风格，但按钮改成明确双入口：

- `快速识别`
- `AI 一键分析整个文件`

若文件尚未选择，则两者都先触发文件选择。

### 7.2 AI 分析态

点击 `AI 一键分析整个文件` 后：

- 显示覆盖右侧主区域的非透明 loading 面板
- 文案明确为：
  - `AI 正在分析整份文档`
  - `正在理解题目结构与图片内容，请稍候`
- 若后端返回错误：
  - 立即关闭 loading
  - 显示明确错误提示
  - 不允许用户一直等待

### 7.3 审核态

审核页新增来源标识：

- `快速识别`
- `AI 深度分析`

左侧题卡对 `异常` 更高亮，对 `缺答案` 保持非阻断提醒。

### 7.4 用户心智

老师不需要理解底层模型，只需要理解两件事：

- 快速识别适合规范文档
- AI 一键分析适合复杂文档和图片题

## 8. 后端接口设计

### 8.1 请求模型扩展

`QuestionImportDocumentRecognizeRequest` 扩展字段：

- `analysis_mode: "fast" | "ai_full"`
- `images: list[QuestionImportImageInput]`

新增图片输入模型：

- `image_id`
- `url`
- `order`
- `page`
- `alt`

### 8.2 响应模型扩展

`QuestionImportDraft` 扩展：

- `images`
- `recognition_mode`
- `comparison_flags`

其中 `comparison_flags` 用于记录：

- `count_mismatch`
- `type_mismatch`
- `low_similarity`
- `missing_options`
- `image_unmatched`

### 8.3 服务层拆分

服务层新增三个明确函数：

- `segment_question_document_by_blocks`
- `recognize_question_document_with_ai`
- `merge_ai_and_rule_recognition`

原来的单题 `recognize_imported_question` 继续保留，作为局部补全能力。

## 9. 错误处理

### 9.1 后端错误

- AI 超时：返回明确业务错误
- AI 返回非 JSON：返回 `AI 分析结果格式异常`
- 图片 URL 不可访问：记录 warning，并在结果中标识相关题需人工核对
- 文档空内容：直接 400

### 9.2 前端反馈

任何导入识别失败都必须：

- 结束 loading
- 显示错误 alert/toast
- 保留重新尝试入口

不允许出现“用户一直等待但页面没有反馈”的状态。

## 10. 测试设计

### 10.1 后端测试

- 模板文档按 `[题型]` 正确切题
- 非模板文档按段落与序号正确切题
- `[答案] / [解析] / [难度]` 正确附着到当前题
- 含图片锚点的文本能正确进入 AI 请求
- AI 返回非法 JSON 时正确报错
- AI 与 baseline 数量冲突时正确标记异常

### 10.2 前端测试

- 上传后能看到 `快速识别` 和 `AI 一键分析整个文件`
- AI 分析时显示固定 loading 面板
- 出错后 loading 立即关闭
- AI 结果中的异常题在左侧正确显示
- 图片题在审核区中能正确显示图片内容

## 11. 实施顺序

1. 先增强规则分题，统一段落块与字段边界逻辑
2. 再扩展前后端请求结构，让图片可进入识别链路
3. 新增整份文档 AI 识别服务与严格 JSON 校验
4. 完成 AI 与 baseline 比对和异常标记
5. 最后改前端双入口、loading 和审核态来源标识

## 12. 决策结论

本次导入增强采用：

- 双入口：`快速识别` + `AI 一键分析整个文件`
- 双引擎：规则 baseline + AI 全文分析
- AI 图文混合输入
- AI 结果必须输出严格 JSON
- AI 结果必须与规则结果比对，不允许裸用

这是当前“稳定性、智能性、可维护性”之间最平衡的方案。
