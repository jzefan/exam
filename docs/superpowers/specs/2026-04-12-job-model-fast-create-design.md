# 岗位模型快速生成工具优化方案

## 1. 背景

当前平台已经具备：

1. 岗位模型基础结构
2. `专业 -> 方向 -> 技能 -> 知识点` 的知识图谱
3. 岗位模型相关页面与快速生成原型

当前平台尚不具备：

1. 可直接复用的标准岗位模型内容库

本次优化目标不是重做一套岗位模型系统，而是在现有结构之上，补齐“标准岗位模型内容层”，并围绕企业上传场景做一条完整的智能闭环。

## 2. 产品目标

围绕 `解析 -> 生成 -> 校准 -> 输出` 形成岗位模型生成闭环：

1. 平台侧可快速建设标准岗位模型
2. 企业侧可基于标准岗位快速生成企业版岗位模型
3. 输出结果以“在线持续编辑的岗位模型”为主
4. 支持版本控制

## 3. 产品定位

### 3.1 一句话定位

一个以“标准先行，企业校准”为原则的岗位模型智能生成工具。

### 3.2 核心原则

1. 先有标准基底，再生成企业版本
2. 企业版模型允许包含企业专属能力项
3. 平台标准与企业版本分层管理，避免相互污染
4. 第一阶段暂不支持企业版本反向沉淀为平台标准

## 4. 标准岗位模型来源

平台当前没有现成的标准岗位模型内容，因此标准岗位模型的形成来源定义为：

`1650分类框架 + 平台知识图谱 + AI生成草案 + 人工定版`

### 4.1 各部分职责

1. `1650分类框架`
   - 提供 `16个产业 -> 50个产业方向` 的组织框架
   - 定义岗位所属产业归属

2. `平台知识图谱`
   - 提供技能、知识点等能力素材
   - 作为岗位模型内容生成与映射的能力底座

3. `AI生成草案`
   - 根据岗位名称、产业方向、知识图谱内容快速生成标准岗位草案

4. `人工定版`
   - 对标准岗位模型进行确认、调整、发布
   - 形成平台可信标准内容

## 5. 信息架构建议

### 5.1 标准库组织方式

推荐采用：

`16个产业 -> 产业方向 -> 具体岗位`

补充说明：

1. 前台核心沉淀单位是“具体岗位”
2. `产业方向` 不是纯标签，而是结构字段
3. `岗位族` 可作为后台辅助归类字段保留，但不作为第一阶段主视图中心

### 5.2 为什么不把方向只做标签

如果产业方向只是标签：

1. 标准库结构会变松散
2. 难以做标准建设与统计分析
3. 企业匹配路径会变得不稳定

因此建议：

1. 数据模型中将方向作为正式字段
2. 交互层可视情况弱化为筛选、面包屑或归属说明

## 6. 第一阶段双入口策略

第一阶段采用“双入口”，但以企业场景为主。

### 6.1 企业快速生成入口

主流程：

1. 上传 JD / 岗位说明书 / 任职资格
2. 系统解析文本
3. 推荐最接近的标准具体岗位模型
4. 自动识别企业差异
5. 自动建议企业新增能力项
6. 企业在线校准
7. 生成企业版岗位模型并进入版本管理

### 6.2 平台标准建设入口

主流程：

1. 选择产业、方向、岗位
2. 从知识图谱召回相关技能与知识点
3. AI 生成标准岗位模型草案
4. 人工校准
5. 发布为平台标准岗位模型

## 7. 企业侧核心闭环

企业侧闭环定义为：

`解析 -> 命中标准岗位 -> 差异识别 -> 企业校准 -> 在线输出`

### 7.1 输出原则

默认输出物不是报告，而是“在线持续编辑的岗位模型”。

### 7.2 企业版模型构成

企业版岗位模型由三类内容组成：

1. `标准项`
2. `企业调整项`
3. `企业新增项`

### 7.3 企业新增项原则

企业新增项的主来源为 AI 自动识别，但企业需要保留手工补充能力。

第一阶段产品优先级：

1. AI 自动建议企业新增项
2. 企业手工补充作为必要兜底能力

## 8. 校准工作台设计方向

采用 `单列校准式`，不采用左右双栏强对照作为主形态。

### 8.1 主视图特点

用户看到的是一个企业版岗位模型草案，每个能力项带有明确来源标记：

1. `标准项`
2. `企业调整`
3. `企业新增`

### 8.2 每个能力项建议展示的信息

1. 能力项名称
2. 能力等级 / 熟练度
3. 来源状态
4. 关联知识点
5. AI 生成依据摘要
6. 是否允许删除 / 恢复标准项

### 8.3 展开层可查看

1. 标准原始内容
2. 企业文档命中证据
3. AI 建议理由
4. 修改记录

## 9. 与现有系统结合方式

### 9.1 复用内容

1. 现有岗位模型结构
2. 现有知识图谱结构
3. 现有岗位模型页面和基础路由

### 9.2 新增内容

1. 标准岗位模型内容层
2. 企业上传解析能力
3. 标准岗位推荐与匹配逻辑
4. 差异识别与企业新增能力识别
5. 企业版本控制

## 10. 第一阶段范围建议

为了避免标准内容建设过重，建议第一阶段不要一次覆盖全部产业和岗位，而是：

1. 先选重点产业方向
2. 每个方向先建设少量高频岗位
3. 跑通企业上传生成链路
4. 再逐步扩展标准岗位库

## 11. 关键产品决策结论

本轮头脑风暴已确认：

1. 采用 `标准先行，企业校准`
2. 标准结构采用 `产业 -> 产业方向 -> 具体岗位`
3. 平台标准岗位核心沉淀单位是“具体岗位”
4. 企业上传后，先推荐一个最接近的标准岗位，再生成企业版
5. 企业版支持企业专属能力项
6. 校准工作台使用单列视图
7. 默认输出为在线持续编辑的岗位模型
8. 第一阶段支持双入口，但企业入口为主
9. 企业版本未来可以考虑反向沉淀平台标准，但当前阶段暂不支持

## 13. 页面级信息架构

基于现有岗位模型模块，建议第一阶段形成 4 个核心页面。

### 13.1 页面一：标准岗位库

定位：

平台标准岗位模型的浏览与选择入口。

建议结构：

1. 顶部：搜索、产业筛选、方向筛选、岗位状态筛选
2. 左侧：`16个产业` 导航
3. 中部：标准岗位列表
4. 列表项信息：
   - 岗位名称
   - 所属产业
   - 所属方向
   - 标准状态（草案 / 已发布）
   - 最近更新时间
   - 关联知识点数量
5. 操作：
   - 查看详情
   - 进入标准建设
   - 作为企业校准基底

### 13.2 页面二：企业快速生成入口

定位：

企业用户上传材料，快速生成企业版岗位模型的主入口。

建议结构：

1. 输入区
   - 粘贴 JD / 任职资格
   - 上传 PDF / Word / 图片
2. 标准命中区
   - 展示系统推荐的标准具体岗位
   - 显示所属产业、方向、匹配理由
3. 解析摘要区
   - 提取出的核心职责
   - 提取出的工具 / 技术 / 资格要求
   - 识别出的可能企业新增能力项
4. 主操作：
   - 使用推荐标准岗位继续
   - 重新选择标准岗位

### 13.3 页面三：岗位模型校准工作台

定位：

企业版岗位模型生成后的核心编辑页。

主视图采用单列校准式。

建议结构：

1. 顶部信息栏
   - 岗位名称
   - 所属产业 / 方向
   - 当前版本
   - 状态（草稿 / 已发布）
2. 左侧辅助栏
   - 模块导航：概览、能力维度、技能、知识点、变更记录
   - 差异筛选：全部 / 标准项 / 企业调整 / 企业新增
3. 中部主内容
   - 按维度展示能力结构
   - 每项标记来源状态
   - 支持展开查看证据与 AI 理由
4. 右侧上下文栏
   - 企业原文命中片段
   - 标准基底说明
   - 关联知识点与教学建议
5. 底部或顶部操作
   - 保存草稿
   - 发布新版本
   - 查看版本差异

### 13.4 页面四：标准岗位建设工作台

定位：

给平台运营 / 专家建设标准岗位模型的后台页面。

建议结构：

1. 基础信息区
   - 产业
   - 产业方向
   - 岗位名称
   - 岗位说明
2. AI 生成区
   - 从知识图谱召回候选技能与知识点
   - 生成标准草案
3. 审核区
   - 调整维度
   - 调整技能等级
   - 删除不合适项
   - 增补标准项
4. 发布区
   - 发布为标准岗位模型
   - 留版本说明

1. `industry_code`

## 15. AI 流程拆解

第一阶段不建议把 AI 做成一个黑盒“直接生成完整模型”，而建议拆成若干可解释步骤。

### 15.1 企业入口的 AI 流程

#### Step 1：文档解析

输入：

1. JD
2. 岗位说明书
3. 任职资格

输出：

1. 岗位名称候选
2. 核心职责
3. 任职要求
4. 工具 / 技术 / 证书 / 业务关键词

#### Step 2：标准岗位推荐

输入：

1. 解析后的岗位信息
2. `16个产业 -> 产业方向 -> 标准岗位`

输出：

1. 最接近的标准岗位
2. 匹配理由
3. 所属产业、方向

#### Step 3：差异识别

基于标准岗位模型与企业文档，识别：

1. 标准项中被强调的部分
2. 企业需要调整的标准项
3. 标准模型中缺失但企业材料出现的新增项

#### Step 4：企业版模型生成

输出：

1. 标准项
2. 企业调整项
3. 企业新增项
4. 每项的依据摘要

### 15.2 平台标准建设的 AI 流程

1. 选择产业、方向、岗位
2. 从知识图谱召回候选技能与知识点
3. 生成标准草案
4. 专家校准
5. 发布标准

## 16. 第一阶段功能边界

### 16.1 第一阶段要做

1. 企业上传入口
2. 标准岗位推荐
3. 基于标准岗位生成企业版草案
4. 支持企业调整和新增能力项
5. 在线保存与版本控制
6. 标准岗位建设后台

### 16.2 第一阶段暂不做

1. 企业版本自动反向沉淀为平台标准
2. 全量覆盖所有产业方向与岗位
3. 高复杂度对比报告生成
4. 多组织共享的复杂标准审批流

## 17. 第一阶段实施建议

### Phase 1：先补标准内容建设能力

1. 为岗位模型补充产业、方向、模型类型等字段
2. 建标准岗位建设入口
3. 先沉淀一批重点岗位标准模型

### Phase 2：再补企业快速生成入口

1. 上传材料
2. 文档解析
3. 标准岗位推荐
4. 企业版草案生成

### Phase 3：完善校准与版本能力

1. 单列校准工作台
2. 差异状态标记
3. 版本历史与版本说明

## 18. 对现有原型页的判断

当前 [fast-create.tsx](/Users/jzefan/work/proj/exam/frontend/src/pages/job-models/fast-create.tsx) 更接近一个“AI 上传演示页”，但距离本次要实现的产品目标还有几个明显缺口：

1. 没有真正体现“先命中标准岗位，再企业校准”
2. 没有标准来源和产业方向归属
3. 没有 `标准项 / 企业调整 / 企业新增` 语义
4. 版本控制只停留在展示层，没有产品语义闭环

因此建议：

1. 不废弃该页面
2. 将其演进为“企业快速生成入口”
3. 新增“标准岗位建设入口”和“标准岗位库”
