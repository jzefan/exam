# 岗位-课程全景图谱工作台设计规格

## 1. 目标

将岗位模型模块从“树状编辑器”升级为“岗位-课程全景图谱工作台”。

第一版重点不是重构所有业务数据，也不是做通用白板工具，而是让用户能在一张图里完成四件事：

1. 查看所有岗位和课程的全景关系。
2. 选中一个岗位，查看岗位技能以及这些技能关联了哪些课程。
3. 选中一个课程，查看有哪些岗位/技能关联它，以及课程知识树中哪些知识点被映射。
4. 通过拖线建立技能-课程映射，以及岗位知识点-课程知识点映射。

## 2. 设计原则

### 2.1 保留现有数据体系

第一版不推翻现有岗位模型数据结构。

现有岗位侧结构保持：

```text
JobModel
  -> JobModelVersion
    -> CompetencyDimension
      -> Skill
        -> SkillKnowledgePoint
```

展示心智调整为：

```text
岗位
  -> 技能
    -> 岗位知识点
```

其中 `CompetencyDimension` 不作为主路径节点展示，而作为技能的分组、标签、筛选条件。

### 2.2 不新增第二套课程体系

课程直接复用现有知识体系中的主知识点。

现有课程/知识结构是：

```text
专业 Major
  -> 方向 Direction
    -> 主知识点 Root KnowledgePoint（展示为课程）
      -> 子知识点 Child KnowledgePoint
```

图谱中的“课程卡片”只是 `Root KnowledgePoint` 的展示别名，不新增 `Course` 表，避免两套课程体系脱节。

### 2.3 图谱优先，列表保留

`/gwmx/job-models` 第一版应逐步成为岗位-课程图谱默认入口。

原岗位列表、标准库、岗位编辑器继续保留，作为管理视图和精细编辑入口。

## 3. 核心对象

### 3.1 岗位卡片

来源：`JobModel`。

岗位卡片表示一个岗位模型资产，而不是某个树节点。

小卡片默认展示：

- 岗位名称
- 产业/方向
- 技能数量
- 版本/状态

点击后卡片放大，并进入岗位焦点态。

### 3.2 技能卡片

来源：`Skill`。

技能是岗位下的一级能力单元。用户心智中，“技能”比“知识点”更符合行业表达，因此第一层采用“岗位 -> 技能”。

技能卡片展示：

- 技能名称
- 关联课程数
- 技能下岗位知识点数

能力维度、等级、来源等作为标签或详情字段，不作为图谱主路径。

### 3.3 岗位知识点节点

来源：`SkillKnowledgePoint`。

岗位知识点是技能下的细粒度要求。

岗位知识点不直接关联课程整体，只能映射到某个课程知识树中的具体知识点。

### 3.4 课程卡片

来源：全局 `KnowledgePoint` 中的根/主知识点。

课程卡片展示：

- 课程名称
- 子知识点数
- 关联的技能数
- 资料数量

展示形式建议为紧凑指标：

```text
知识点 36 · 技能 4 · 资料 12
```

### 3.5 课程知识点节点

来源：课程主知识点下的任意层级子知识点。

课程知识点用于承接岗位知识点映射。

## 4. 关系模型

### 4.1 技能关联课程

业务含义：

```text
Skill -> Root KnowledgePoint(课程)
```

表示某门课程支撑某个岗位技能。

需要新增关系表：

```text
skill_course_mappings
```

建议字段：

```text
id
skill_id
course_root_knowledge_point_id
relation_type
match_type
status
created_by
created_at
updated_at
deleted_at
```

第一版字段语义保持简单：

- `relation_type`: `required` / `supporting`，用户手动画线后选择。
- `match_type`: `manual` / `suggested`。
- `status`: `suggested` / `confirmed` / `rejected`。

注意：关系类型和覆盖率不是第一版核心体验，不应在主界面里抢占注意力。

### 4.2 岗位知识点映射课程知识点

业务含义：

```text
SkillKnowledgePoint -> KnowledgePoint(课程知识树任意节点)
```

第一版沿用并扩展现有 `skill_kp_mappings`。

它已经表达：

```text
skill_kp_id -> knowledge_point_id
```

其中 `knowledge_point_id` 必须理解为全局课程知识点 ID，而不是岗位内部知识点。

建议补充字段：

```text
relation_type
match_type
status
created_by
deleted_at
```

### 4.3 映射依赖规则

岗位知识点到课程知识点的映射必须依附于技能-课程关联。

也就是说，用户只有在：

```text
Skill -> Course
```

已经存在后，才能建立：

```text
SkillKnowledgePoint -> CourseKnowledgePoint
```

如果用户直接从岗位知识点拖线到某课程知识点，而该课程尚未关联当前技能，系统应提示：

```text
需要先将该技能关联到课程，是否同时建立课程关联？
```

删除技能-课程关联时，应同步取消该技能下与该课程知识树相关的细粒度知识点映射。

## 5. 四个主交互状态

第一版以四个主状态组织体验。

### 5.1 全景态

全景态是默认入口。

画布展示所有岗位卡片和课程卡片，不使用传统列表。

布局采用“半结构化地图”：

- 岗位域：展示岗位卡片，按产业方向、岗位族或模型类型分组。
- 课程域：展示课程卡片，按专业、方向分组。
- 中间区域：保留连接线空间。

注意：这里的“岗位域/课程域”不是列表，而是游戏地图式卡片区域。卡片应小而清晰，点击后放大。

无关联冷启动时：

- 仍展示岗位卡片和课程卡片。
- 不画虚假的线。
- 中间显示轻提示：“选择岗位后，可为技能关联课程。”
- 可提供“推荐课程关联”入口，但不自动建立关系。

### 5.2 岗位焦点态

用户点击岗位卡片后进入岗位焦点态。

交互规则：

- 被点击岗位卡片放大，成为当前焦点。
- 一次只展开一个岗位。
- 技能卡片围绕岗位卡片扇形或环形展开。
- 已与技能关联的课程高亮。
- 未关联课程仍可见，但灰化、降低视觉权重。
- 右侧固定详情面板显示岗位/技能编辑信息。

技能卡片操作：

- 点击技能：高亮该技能、显示关联课程线。
- 双击或展开：显示该技能下岗位知识点。
- 从技能拖线到课程：建立技能-课程关联。

### 5.3 课程焦点态

用户点击课程卡片后进入课程焦点态。

交互规则：

- 被点击课程卡片放大，成为当前焦点。
- 一次最多展开一个课程知识树。
- 显示有哪些岗位/技能关联该课程。
- 默认只展开课程第一层子知识点。
- 更深层级按需继续展开。
- 已被当前岗位/技能映射的课程知识点高亮。
- 未映射知识点保持中性展示。

课程详情面板应回答：

- 这门课程关联了哪些岗位？
- 关联了哪些技能？
- 课程知识树中哪些知识点已被岗位知识点映射？
- 还有哪些资料可查看？

### 5.4 映射编辑态

映射编辑态通过拖线进入。

第一版只支持两类映射线：

1. 技能 -> 课程
2. 岗位知识点 -> 课程知识点

不做岗位技能之间、岗位知识点之间、课程知识点之间的自由概念关系线。

拖线规则：

- 从技能拖到课程，创建 `Skill -> Course`。
- 从课程拖到技能，也允许，结果仍统一存为 `Skill -> Course`。
- 从岗位知识点拖到课程知识点，创建 `SkillKnowledgePoint -> KnowledgePoint`。
- 知识点映射必须有上层技能-课程关联。

线创建后使用轻量确认，不弹复杂表单。

## 6. 视觉方向

### 6.1 整体风格

采用“游戏地图 + 专业工作台”的视觉方向。

目标是摆脱传统管理后台列表感，让用户觉得自己在一张人才培养地图里连接岗位需求和课程资源。

### 6.2 岗位卡片

岗位卡片像“职业角色牌 / 任务卡”。

视觉特征：

- 更厚重
- 更有身份感
- 可偏纵向
- 强调岗位名称、产业方向、技能数量、版本状态

### 6.3 课程卡片

课程卡片像“课程据点 / 资源点”。

视觉特征：

- 更轻
- 更偏横向
- 强调课程名称、知识点数、关联技能数、资料数量

### 6.4 放大与聚焦

所有卡片默认是小卡片。

点击后：

- 当前卡片放大。
- 相关节点增强。
- 无关节点灰化但不消失。
- 保留全景上下文。

视觉焦点规则：

- 最后点击的对象成为视觉焦点。
- 之前的上下文继续可见，但降低权重。

## 7. 布局保存

第一版支持版本级共享布局。

规则：

- 初次进入自动排版。
- 用户可拖动卡片和节点位置。
- 拖动后显示“布局已修改”状态。
- 用户点击“保存布局”后，写入当前 `JobModelVersion` 或全景布局配置。
- 再次进入时加载已保存布局。
- 提供“自动排版”按钮，可重新计算布局。

布局保存不创建岗位模型业务版本。

需要新增布局存储：

```text
job_model_graph_layouts
```

建议字段：

```text
id
scope_type        # org_overview | job_model_version
scope_id          # organization_id or job_model_version_id
layout_json
updated_by
updated_at
```

说明：

- 全景态需要组织级 `org_overview` 布局，用于保存所有岗位卡片和课程卡片的位置。
- 单岗位版本内也可能需要 `job_model_version` 布局。
- 当前用户要求“版本即 shared”，第一版不做个人布局。

## 8. 右侧详情面板

右侧固定详情面板是主要编辑区。

单击节点或线后，面板内容随对象变化。

### 8.1 岗位详情

展示：

- 岗位字段信息
- 产业/方向
- 版本状态
- 技能列表摘要
- 快速进入原岗位编辑器

### 8.2 技能详情

展示：

- 技能名称、描述、等级、所属维度
- 关联课程列表
- 技能下岗位知识点列表
- 已映射的课程知识点
- 新增课程关联入口
- 推荐课程关联入口

### 8.3 课程详情

展示：

- 课程名称、专业、方向
- 子知识点数
- 资料数量
- 关联岗位列表
- 关联技能列表
- 已映射知识点列表
- 跳转课程详情页

### 8.4 映射线详情

展示：

- 起点对象
- 终点对象
- 当前关系类型
- 删除映射
- 确认/忽略建议映射

## 9. 推荐映射

推荐只作为辅助，不作为第一版主体验。

触发方式：

- 选中岗位：推荐该岗位的课程关联。
- 选中技能：推荐该技能关联课程。
- 选中技能 + 课程：推荐知识点映射。

推荐结果：

- 不展示推荐理由。
- 不保存内部证据、匹配信号或解释。
- 只保存最小映射字段。
- 用户可以确认、删除或修改。

推荐策略：

- 第一版采用规则候选 + LLM 复核。
- 先用名称、描述、知识点关键词找候选。
- 再由 LLM 做语义判断。
- 结果以 `status=suggested` 保存。

## 10. API 设计方向

需要新增一个面向图谱的聚合接口，避免前端为每个节点反复请求。

建议接口：

```text
GET /api/job-models/graph/overview
```

返回：

- 岗位卡片
- 技能摘要
- 课程卡片
- 技能-课程映射线
- 统计字段
- 当前全景布局

```text
GET /api/job-models/graph/jobs/{job_model_id}
```

返回某个岗位焦点所需数据：

- 岗位详情
- 技能列表
- 技能下岗位知识点
- 已关联课程
- 映射线

```text
GET /api/job-models/graph/courses/{course_root_kp_id}
```

返回某个课程焦点所需数据：

- 课程详情
- 课程第一层知识点
- 关联岗位/技能
- 已映射课程知识点

```text
POST /api/job-models/graph/skill-course-mappings
DELETE /api/job-models/graph/skill-course-mappings/{id}
PATCH /api/job-models/graph/skill-course-mappings/{id}
```

管理技能-课程映射。

```text
POST /api/job-models/graph/knowledge-point-mappings
DELETE /api/job-models/graph/knowledge-point-mappings/{id}
PATCH /api/job-models/graph/knowledge-point-mappings/{id}
```

管理岗位知识点-课程知识点映射。

```text
PUT /api/job-models/graph/layouts/{scope_type}/{scope_id}
```

保存布局。

## 11. 第一版非目标

第一版不做：

- 通用白板工具。
- 多岗位同时展开。
- 多课程知识树同时展开。
- 任意知识框之间的自由概念线。
- 复杂覆盖率报表作为主界面重点。
- 推荐理由展示。
- 推荐证据存储。
- 个人布局覆盖。
- 实时多人协作。
- 新建第二套课程表。

## 12. 第一版用户路径

### 12.1 查看全景

1. 用户进入岗位模型模块。
2. 看到所有岗位卡片和课程卡片。
3. 没有关联时，画布呈现为待连接工作台。
4. 有关联时，显示岗位技能到课程的关系线。

### 12.2 查看岗位

1. 用户点击岗位卡片。
2. 岗位放大。
3. 技能围绕岗位展开。
4. 已关联课程亮起。
5. 用户点击技能，在右侧查看技能详情。

### 12.3 关联课程

1. 用户选中岗位。
2. 展开技能。
3. 从技能拖线到课程。
4. 系统创建技能-课程关联。
5. 关联课程立即高亮。

### 12.4 查看课程

1. 用户点击课程卡片。
2. 课程放大。
3. 右侧显示关联岗位和技能。
4. 课程第一层知识点展开。
5. 已被映射的课程知识点高亮。

### 12.5 映射知识点

1. 用户选中技能。
2. 展开技能下岗位知识点。
3. 选中已关联课程。
4. 展开课程知识树。
5. 从岗位知识点拖线到课程知识点。
6. 系统保存细粒度映射。

## 13. 与现有页面关系

### 13.1 岗位列表

保留为列表视图。

入口可以在图谱顶部提供：

```text
切换到列表
```

### 13.2 原岗位编辑器

保留为精细编辑器。

图谱中岗位详情面板提供：

```text
进入完整编辑器
```

### 13.3 课程详情页

保留为课程管理页面。

课程详情面板提供：

```text
查看课程详情
```

## 14. 待实现优先级

### P0：图谱数据聚合

- 新增 overview 聚合接口。
- 复用 JobModel 和 Root KnowledgePoint。
- 返回岗位卡片、课程卡片、现有映射关系。

### P1：全景态画布

- 岗位卡片和课程卡片地图式展示。
- 支持缩放、平移、选中、放大。
- 无关联冷启动可用。

### P2：岗位焦点态

- 点击岗位展开技能。
- 高亮关联课程。
- 右侧技能详情面板。

### P3：课程焦点态

- 点击课程展开课程知识树第一层。
- 展示关联岗位/技能。
- 高亮已映射知识点。

### P4：映射编辑

- 技能拖线到课程。
- 岗位知识点拖线到课程知识点。
- 删除映射。

### P5：布局保存

- 自动排版。
- 手动拖动。
- 保存版本级共享布局。
- 恢复自动排版。

### P6：推荐映射

- 按焦点触发推荐。
- suggested 线展示。
- 用户确认/拒绝/删除。
