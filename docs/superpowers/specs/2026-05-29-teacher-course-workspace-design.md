# 教师课程工作区设计

## 背景

从教师视角看，课程是教学工作的主要观察单位。教师并不是先想“我要管理知识点、题库、考试或资料”，而是先进入某门课程，再围绕这门课程查看和组织：

- 课程资料
- 考试
- 作业/练习
- 题目
- 知识结构
- 批改与教学待办

当前系统已经具备这些能力，但入口分散在“题库管理”“考试管理”“阅卷中心”“知识点管理”等模块中。尤其是“知识点管理”使用的是系统内部语言，对教师来说更自然的表达应是“我的课程”。

## 目标

- 教师角色新增一个主入口：`我的课程`。
- `我的课程` 承接当前题库管理中的“知识点管理”能力，但用教师语言组织。
- 点击某个课程后进入课程工作台式详情页。
- 课程工作台聚合显示课程资料、考试、作业/练习、题目、知识结构和待办。
- 保持当前其它系统功能不变：考试管理、题库管理、阅卷中心、导入流程和知识结构维护能力继续存在。
- 课程概念复用现有主知识点，不新增独立 `Course` 实体。

## 非目标

- 不重构现有考试、题库、阅卷、导入模块的主流程。
- 不把现有题目、考试、资料全部迁移到新表。
- 不新增独立课程数据模型。
- 不删除题库管理下的题目列表、创建题目、导入题目、标签管理等入口。
- 不在第一期改变学生端的信息架构。

## 概念定义

### 课程

课程就是现有知识结构中的主知识点：

```text
专业 -> 方向 -> 主知识点
```

其中 `主知识点` 在教师侧显示为课程。课程 ID 使用现有 `root_knowledge_point_id`。

### 专业直属课程

主知识点也可以挂在专业下。教师侧统一理解为：

```text
专业 -> 课程
```

UI 中可显示为“专业直属”或“未分方向”，避免教师必须理解内部的方向兼容机制。

实现上第一期兼容现有数据结构：

- 课程有方向时，按 `专业 / 方向 / 课程` 展示。
- 通过现有前端创建“专业下主知识点”时，继续使用默认方向承接，并在教师 UI 中展示为“专业直属”。
- 本期不扩展无方向根节点写入能力，避免影响现有知识点管理接口。

## 方案对比

### 方案 A：前端聚合跳转页

新增课程列表页，点击课程后提供到考试、题库、资料、知识点的筛选跳转。

优点：

- 改动小。
- 可以快速让教师按课程进入相关内容。

缺点：

- 课程页缺少稳定统计和待办。
- 仍像导航中转站，不像教师主工作区。
- 后续会继续把课程信息散落到各个模块。

### 方案 B：课程工作区视图层

新增教师课程入口和课程详情工作台。底层仍使用主知识点，后端提供课程聚合 API，前端按课程展示跨模块摘要和列表。

优点：

- 符合教师“先看课程”的心智。
- 不破坏当前模块和数据模型。
- 能逐步把资料、考试、作业、题目、知识结构收口到课程下。
- 与现有 `root_knowledge_point_id` 体系兼容。

缺点：

- 需要新增聚合 API 和课程工作台页面。
- 需要明确不同模块与课程的关联统计规则。

### 方案 C：新增 Course 实体

新增独立课程表，并把题目、考试、资料等都迁移为显式关联课程。

优点：

- 长期语义最清晰。

缺点：

- 影响现有模型和大量业务流程。
- 需要迁移历史数据。
- 不符合“当前其它系统功能不变”的约束。

## 结论

采用方案 B：课程工作区视图层。

课程工作区是教师侧新增主入口，不替换底层模型，不影响现有系统功能。课程的唯一标识使用主知识点 ID。

## 导航设计

教师与 evaluator 角色顶部导航新增：

- `我的课程`

导航顺序：

```text
工作台 / 我的课程 / 阅卷中心 / 考试管理 / 题库管理
```

题库管理继续保留：

- 题目列表
- 创建题目
- 导入题目
- 标签管理

“知识点管理”能力迁移到“我的课程”主入口承接。第一阶段题库管理中保留旧“知识点管理”入口，但它作为兼容入口指向 `/courses` 或同一课程管理页面。

旧入口的文案调整为“课程知识结构”，避免教师看到两套互相竞争的概念。

## 页面设计

### 我的课程列表页

路由：

```text
/courses
```

页面内容：

- 左侧或顶部按专业分组展示课程。
- 支持搜索课程名。
- 支持按专业、方向筛选。
- 课程卡片显示：
  - 课程名称
  - 所属专业
  - 所属方向或“专业直属”
  - 资料数量
  - 考试数量
  - 作业数量
  - 题目数量
  - 待处理数量

课程列表的数据来源是可见的根知识点。

### 课程工作台页

路由：

```text
/courses/:courseId
```

其中 `courseId` 是主知识点 ID。

页面结构：

- 顶部：课程名称、专业/方向路径、课程说明、主要操作。
- 摘要卡片：
  - 课程资料
  - 考试
  - 作业
  - 题目
  - 待办
- 标签页：
  - `课程资料`
  - `考试`
  - `作业`
  - `题目`
  - `知识结构`
- 右侧或下方待办区：
  - 待阅卷考试
  - 待批改作业
  - 新导入题目待确认知识点
  - 资料可生成题目的提示

### 课程资料

复用现有知识点资源能力。课程资料可以挂在课程节点，也可以挂在课程下的子知识点节点。

课程工作台中默认展示整门课程范围内的资料：

- 课程节点资料
- 子知识点资料

操作：

- 上传资料
- 添加外部链接
- 预览资料
- 从资料生成题目

### 考试

展示与该课程相关的考试。

关联规则：

- 考试题目中包含该课程或其子知识点下的题目，则考试属于该课程。
- 如果考试后续有显式 `root_knowledge_point_id`，优先使用显式字段。

操作：

- 查看考试
- 创建考试，默认带入当前课程筛选
- 进入考试分析

### 作业

教师侧使用“作业”表达，底层复用现有 `practice`。

展示规则：

- `exam.category = "practice"` 的记录在教师课程页显示为作业。
- 作业范围按当前课程或其子知识点过滤。

操作：

- 发布作业，默认带入当前课程
- 查看作业提交情况
- 进入批改或结果分析

### 题目

展示该课程及其子知识点关联的题目。

操作：

- 查看题目
- 创建题目，默认带入当前课程
- 导入题目，默认带入当前课程
- 按知识点、题型、难度筛选

### 知识结构

复用当前知识点管理的树形能力。

教师在课程工作台中看到的是当前课程的子知识结构，而不是完整“专业/方向/所有主知识点”管理视图。

操作：

- 查看课程知识树
- 新增子知识点
- 编辑知识点
- 管理前置依赖
- 查看节点资料和题目

## 后端 API 设计

新增课程聚合 API，前缀使用：

```text
/api/teacher/courses
```

### 课程列表

```text
GET /api/teacher/courses
```

返回教师可见的主知识点列表，以及课程摘要：

- id
- name
- description
- major_id
- major_name
- direction_id
- direction_name
- display_path
- is_major_direct
- material_count
- exam_count
- assignment_count
- question_count
- pending_count

### 课程详情摘要

```text
GET /api/teacher/courses/{course_id}
```

返回课程详情和工作台摘要。

### 课程资料

```text
GET /api/teacher/courses/{course_id}/materials
```

返回课程节点及子知识点节点下的资料。

### 课程考试

```text
GET /api/teacher/courses/{course_id}/exams
```

默认返回 `category = "exam"`。

### 课程作业

```text
GET /api/teacher/courses/{course_id}/assignments
```

底层查询 `category = "practice"`。

### 课程题目

```text
GET /api/teacher/courses/{course_id}/questions
```

返回课程及其子知识点关联题目。

### 课程知识结构

新增课程范围接口：

```text
GET /api/teacher/courses/{course_id}/knowledge-tree
```

返回以课程节点为根的子树。

## 数据关联规则

### 子树范围

课程范围包含：

- 课程主知识点本身
- 所有 descendant 子知识点

后端应提供统一的 `course_subtree_ids(course_id)` 查询逻辑，避免考试、题目、资料各自实现不一致。

### 题目统计

题目属于课程，当它关联的任一知识点在课程子树内。

### 考试统计

考试属于课程，当考试中任一题目关联到课程子树内知识点。

### 作业统计

作业属于课程，当 `category = "practice"` 且作业题目关联到课程子树内知识点。

### 资料统计

资料属于课程，当资料挂载节点是课程节点或课程子知识点节点。

## 权限

遵循现有教师资源可见性规则：

- 教师可见自己拥有的私有课程。
- 教师可见平台共享课程。
- 平台管理员、学校管理员可见更广范围。
- 教师只能修改自己有写权限的课程知识结构和课程资源。

课程工作台不提升权限，只是聚合展示用户本来可访问的内容。

## 前端组件

新增页面：

- `frontend/src/pages/courses/list.tsx`
- `frontend/src/pages/courses/detail.tsx`

可复用能力：

- `KnowledgePointSelector`
- 当前知识点管理中的专业/方向/主知识点列表能力
- 当前知识树画布或其课程子树版本
- 题目列表中的题目卡片/筛选逻辑
- 考试列表中的考试卡片/状态徽标
- 资料弹窗与资料生成题目能力

抽取轻量共享模块：

- `course-api.ts`
- `course-types.ts`
- `CourseSummaryCards`
- `CourseWorkspaceTabs`
- `CourseKnowledgeTree`

## 迁移与兼容策略

第一阶段：

- 新增 `我的课程` 导航。
- 课程列表使用新增课程聚合接口。
- 点击课程进入课程工作台。
- 题库管理下旧“知识点管理”入口保留为兼容入口，降低迁移风险。

第二阶段：

- 将教师常用的课程知识结构维护入口引导到课程工作台。
- 题库管理下如继续保留知识点入口，应使用“课程知识结构”文案，避免双重心智。

第三阶段：

- 如果后续确认需要彻底支持“专业直属主知识点”而不依赖默认方向，再单独设计后端模型和 API 扩展。

## 测试策略

后端测试：

- 课程列表只返回教师可见主知识点。
- 专业/方向/课程路径显示正确。
- 专业直属课程显示为“专业直属”。
- 课程子树题目统计正确。
- 考试和作业按课程子树过滤正确。
- 资料按课程子树过滤正确。
- 教师不能看到或修改无权限资源。

前端测试：

- 教师导航出现“我的课程”。
- 课程列表按专业分组。
- 点击课程进入 `/courses/:courseId`。
- 课程工作台显示资料、考试、作业、题目、知识结构标签。
- 作业标签显示 practice 数据。
- 从课程页创建/导入内容时默认带入当前课程。

## 一期实施决策

- 课程工作台内嵌完整的资料、考试、作业、题目、知识结构标签页，不只做摘要跳转。
- 课程知识结构使用课程子树视图，避免在课程详情中展示其它课程的主知识点。
- 题库管理下旧“知识点管理”入口第一期保留为兼容入口，文案改为“课程知识结构”，并指向新的课程入口或同一页面。
- 作业在教师课程页中统一显示为“作业”，底层继续使用 `practice`。
- 课程继续复用主知识点，不新增 `Course` 表。
